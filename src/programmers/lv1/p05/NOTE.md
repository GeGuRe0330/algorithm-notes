## 문제 요약

덧셈·뺄셈 수식이 문자열로 담긴 배열(길이 1~10)이 주어진다. 수식은 `X 연산자 Y = Z` 모양이고 숫자와 연산자 사이에는 공백이 하나씩 있으며, 음수는 숫자 바로 앞에 `-`가 붙는다(`-3`). 각 수식이 맞으면 `"O"`, 틀리면 `"X"`를 같은 순서로 담은 배열을 반환한다.

## 접근

1. 수식 하나를 공백으로 `split(" ")`하면 `["X", "연산자", "Y", "=", "Z"]` 다섯 조각이 된다. 인덱스 `0`, `2`, `4`가 숫자이고 `1`이 연산자다.
2. 음수 `-3`은 공백 없이 한 조각이라 `Integer.parseInt("-3")`이 그대로 처리한다. 연산자 `-`는 공백으로 둘러싸여 있어서 음수의 `-`와 헷갈리지 않는다.
3. 연산자가 `+`인지 `-`인지를 `switch`로 가르고, `X 연산자 Y`의 계산 결과가 `Z`와 같으면 `"O"`, 아니면 `"X"`를 결과 배열의 같은 위치에 담는다.
4. 개선할 수 있는 점: `split`을 숫자 하나 꺼낼 때마다 다시 하고 있다(수식당 4번). 한 번만 쪼개서 변수에 담으면 더 읽기 쉽다. `default` 분기는 제한사항상 실행되지 않는다.
5. 직접 돌려 본 경계 입력(`0 + 0 = 0`, `-3 - -4 = 1`, `±10000` 근처 값, 틀린 식)에서도 모두 정답이었다.

**풀이 중 생각 메모**
- 먼저 quiz 배열에서 하나 꺼낸다음 split을 하면 되겠다.
- switch문으로 사칙연산(조건에 + or - 만 있다했으니 더 쉽겠네.)을 구별해서 계산한다음 맞는지 비교하는 로직만 넣으면 되겠네.
- quiz의 길이는 최대 10개, 리턴은 "O"인지 "X"인지 들어있는 배열.

## 복잡도
- 시간: O(N × L) — N은 수식 개수(최대 10), L은 수식 길이. 수식마다 `split`을 4번 하지만 N이 작아 사실상 상수.
- 공간: O(N) — 결과 배열(과 `split`이 만드는 조각들).
