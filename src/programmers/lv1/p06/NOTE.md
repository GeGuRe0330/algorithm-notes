## 문제 요약

2 이상 100만 이하의 자연수 `n`이 주어진다. 1부터 `n`까지의 소수가 몇 개인지 반환한다. 소수는 1과 자기 자신으로만 나누어지는 수이고, 1은 소수가 아니다.

## 접근

1. 소수의 정의를 코드로 옮긴다: "나누어떨어지는 수가 하나도 없으면 소수". `2`부터 `n`까지 각 수 `i`에 대해 `j`로 나눠 보고, `i % j == 0`인 `j`를 찾으면 소수가 아니다.
2. `boolean isPrime = true`로 시작해서, 나누어떨어지는 `j`를 찾으면 `false`로 바꾸고 `break`한다. 안쪽 반복이 끝난 뒤 `isPrime`이 `true`이면 한 번만 `answer++`한다. 안쪽 반복이 안 도는 `2`, `3`도 자연스럽게 소수로 세어진다.
3. 처음엔 안쪽 반복 안에서 `i % j != 0`(안 나누어떨어짐)일 때 세어서 결과가 틀렸다. "나누어떨어지지 않는 `j`가 하나라도 있다"와 "나누어떨어지는 `j`가 하나도 없다"는 전혀 다르다. 반복문이 다 끝난 뒤에야 판별할 수 있다.
4. 처음에는 `j`를 `i/2`까지 돌렸는데, `n = 1,000,000`에서 대략 10초 안팎으로 느렸다(추정). 합성수의 약수 짝 `a × b`에서 작은 쪽은 `√i` 이하이므로 `j * j <= i`까지만 나눠 보면 충분하다. 같은 입력에서 약 42ms로 줄었다.
5. 제곱근 함수 대신 `j * j <= i`를 쓰면 정수 계산만 해서 편하고, `j`가 최대 1000 정도라 `int` 오버플로도 없다.
6. 다른 방법: 에라토스테네스의 체로 `2`부터 배수를 지워 나가면 `O(n log log n)`에 구할 수 있다.

**풀이 중 생각 메모**
- 소수 계산 수식을 어케할까나...
- 수의 절반까지만 나눴을 때 안나눠지면 (나머지가 0이면) 되지 않을까?

## 복잡도
- 시간: O(n√n) — 각 수 `i`마다 최대 `√i`번 나눠 본다. 합성수는 약수를 만나면 일찍 끝나서 실제로는 더 빠르다.
- 공간: O(1)
